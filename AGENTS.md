# reerhub-frontend guide (for AI agents)

Next.js 16 App Router + React 19 + Tailwind 4 UI for **REERHUB** (reerhub.com) — India-first tech-job discovery. Teaser-gated public listings (`/jobs`, `/engineering-jobs`, `/ai-jobs`, city + `/remote-jobs`, `/companies`, slug job URLs), protected `/dashboard` with recommendations, passwordless auth, and Pro billing. Live at `https://reerhub.com` (Vercel, auto-deploy on `main` push).

Self-contained repo: product, deployment, design, and decisions live in README and `docs/`. Sibling `reerhub-backend` repo is a separate checkout — never assume shared files. Parent folder is workspace only.

## Runtime

- **Node 24** (`.nvmrc` + `engines`; Node 20 crashes on jsdom). `npm run dev` → `:3000` (needs backend at `:8000` for data).
- Checks: `npx eslint .` (zero errors; `setState` sync-in-`useEffect` is an error — use initializers + key-remount, promise-callback fetches), `npx tsc --noEmit`, regression scripts `test:admin/seo/profile/dashboard/operations/performance/security`, `npm audit --audit-level=high`, `npm run build`. Use actual build output for route counts. A local `--webpack` diagnostic fallback is not proof the standard deployment build passed.
- Version holds (do not bump until upstream supports): `typescript@6` (TS 7 unsupported by typescript-eslint, retry at >=7.1) and `eslint@9` (v10 breaks `eslint-config-next`'s bundled react plugin).

## Conventions

- Brand: `REERHUB`; enterprise: `REERHUB TECHNOLOGIES`; slogan: `Real Effective Engineering Roles Hub`; website: `reerhub.com`. Owner confirmed sole proprietorship registration is complete; remove pending-registration notices. Trademark registration is separate and unconfirmed: do not add ®. Use the enterprise name for legal/business identity, not ordinary product labels. Wordmark uses existing Inter Bold (700) and `BrandWordmark`; preserve the original icon. Ordinary text retains its surrounding weight; do not make every paragraph bold.

- Path alias `@/*`. API: `lib/reerhub.ts` (public reads) + `lib/auth.ts` (`credentials:"include"`, silent refresh retry, `safeNext`, auto CSRF). One global session: `components/AuthProvider.tsx` (`useAuth`) — never add per-page `getMe()` fetches. Guards in `proxy.ts`.
- Styling: follow `docs/design/design-system.md`. All user-facing pages use the approved premium direction: warm white, soft lavender/peach, violet #6d4aff actions, charcoal #241e30 headings, mint/lime accents, Space Grotesk display and original Inter Bold brand. Preserve the expressive homepage animation; other pages use task-aware entrance/interaction motion with stable lists/forms/checkout. Removing animation or reverting this palette requires an explicit user request. Public overrides stay in `.public-site`/public modules; admin retains cobalt and its independent shell. Navigation is full-width at top 0, 72px tall: transparent on home before 32px scroll, 24px frosted glass elsewhere, with an opaque fallback. Verified members use a dedicated 72px search/account top bar and 240px desktop sidebar on all /dashboard routes; one bounded mobile drawer shares those destinations. Public marketing navigation belongs only to visitors. Cookie presence permits neutral loading chrome, never establishes authentication. Map public and legacy links through lib/workspace.ts only after the shared session is confirmed. Public footers are pastel; member pages use compact legal/help footers. Privacy uses Accept/Reject and plain language without internal configuration status. After a choice, no floating privacy launcher or automatic repeat prompt remains; footer Privacy preferences preserves access and focus restoration. Product UI never exposes setup tasks, but retains honest data/action failure notices. Logos use `components/CompanyLogo.tsx`; remote images require configured patterns. Continuous scenes retain pause, offscreen/hidden-tab suspension and static reduced-motion alternatives.
- Anonymous listings show up to 10 previews; full job details and official Apply links are public. Crawlers see identical content. Only eligible active roles emit JobPosting; private/admin pages and staging use noindex and stay out of the adaptive sitemap.
- Breadcrumbs: compact visible public trails match canonical BreadcrumbList markup; member trails start at Overview and omit public schema. Homepage/overview/auth/admin omit trails. Trustpilot is a neutral footer profile link until real reviews support a ratings presentation.
- FAQ/SEO: /faq is the public server-rendered answer source, /dashboard/faq its protected mirror. Only the public FAQ emits FAQPage; Google no longer displays FAQ rich results. One primary H1 and distinct metadata per user route; never duplicate children as a Suspense fallback. Keep the public FAQ outside loading boundaries that hide completed content without JavaScript.
- Analytics: GTM_CONTAINER_ID is a public runtime identifier (owner-provided production default, explicit empty disables, local/test off). GTM runs in the main document on allowlisted public pages only after explicit consent and a confirmed guest session. No tags on member/auth/admin/noindex pages or credential-bearing URLs. Keep denied advertising consent, sanitized public page identity and event allowlists. Entering private pages or withdrawing consent must discard an already measured document; deleting a script cannot unload executed tags. No unconditional noscript tracker. Direct GA4 is an isolated legacy fallback, not installed alongside GTM. GTM does not affect rankings. Container/GA account settings and real receipt need separate verification.
- Secrets: server-only env (`API_URL`, `SITE_URL`, `GOOGLE_CLIENT_ID`, `TURNSTILE_SITE_KEY`) — no `NEXT_PUBLIC_*`. Browser calls same-origin `/api/v1` (rewrite proxies to `API_URL`); `GET /api/config` serves public widget keys at runtime.
- Commits `feat:/fix:/chore:/ci:/docs:`, only when asked. Never commit `.env*`/secrets.
- **Branching: create feature branches from current `origin/main` → test locally → PR directly into `main` → passing CI → explicit owner approval → merge → verify production. Never commit/push directly to `main`. `develop` and staging are retained but paused: no PRs, merges, synchronization pushes or routine releases into `develop` until the owner explicitly resumes them. Approval for a previous release does not authorize a later PR merge. Delete the merged feature branch locally and remotely after production verification.**

## Gotchas

- Public backgrounds are full bleed; content is centered in a 1680px frame with 20–48px gutters. Discovery grids follow container width, stopping at four job columns and eight company tiles. Prose/forms stay readable; billing is capped at 1200px. The homepage uses a 1440px content frame; both the navbar surface and its content row span the available viewport with responsive gutters. Preserve its expressive looping scenes with pause/play, offscreen/tab-hidden suspension and reduced-motion support. All public and member routes now share the approved direction.

- `API_URL`/`SITE_URL` are build-time — Vercel redeploy after changing. Backend CORS must allow the origin + `credentials:true`.
- Backend global rate limit is per process; after running backend tests, wait before live-verifying (15-min window).
- `/dashboard` is the personal overview for Free and Pro. Dedicated /dashboard/jobs, companies, matches, saved, profile, billing and legal/help screens keep the member journey inside the workspace. Legacy `?view=discover|saved|matches`, /profile and /billing links remain compatible through replacement navigation. Recommendations load only for eligible Pro members; overview counts come from saved IDs/profile signals/backend counts, never data export. Preserve distinct readiness/threshold-empty/all-empty/error states and backend-only match evidence.
- Profile uses backend catalog choices: one track, any/up to three roles, ten skills, All India/up to three cities, nonnegative fractional experience. Keep compact searchable checkbox popovers, explicit save/discard and unsaved protection; no custom free-text matching entries. Any work mode maps to `unknown`.
- Shared saved IDs/session reads must stay member-scoped, clear on logout/account switch and serialize refresh. Homepage reads `/home` and the full `/companies` directory concurrently on the server for the all-company logo strip; directory uses 50-item combined reads. Repeated card links disable detail prefetch. Backend owns mutable-content TTL; do not add another independent five-minute SSR cache.
- Weekly JSON import lives in admin Companies: bounded async preview, evidence approval, recent history/recheck/download and Awaiting first sync. Feed availability is not employer ownership. Research is manual on request, checks database identities and previous backend batches, and never uses a seed command. Deploy backend support first.

## Release verification

Use meaningful unit/integration tests for changed behavior, with explicit isolated fixtures and mocked or approved Test-mode providers. Run required checks and review the diff before opening a PR into `main`; CI must pass before asking the owner to approve that merge. For UI changes, verify desktop/mobile and the standard production build. Local tests are not proof of production configuration or delivery: verify the affected production behavior after deployment. Document extra validation and recovery for migrations, auth and billing. Documentation-only changes need proportionate local review; the existing CI gates remain enabled.
